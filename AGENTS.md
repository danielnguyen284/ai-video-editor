# AI Editor project instructions

Read `README.md` for commands and `core/schemas/edit-plan.md` before changing an edit plan.
`core/agent-playbook.md` is the step-by-step that works with this user (analysis, the proposal format, `cut`/`captions`/`preview`, layout defaults, Studio proposals, Windows pitfalls); follow it for every edit so any agent produces the same result.
For every video edit request, first read `core/editing-workflow.md` and `preferences/workflow.json`. Apply standing technical choices without asking again. The chosen default interaction is: analyze the source, propose one concrete treatment, wait for user approval, then build.

## Workflow

- Act as the Editor using `core/roles.md`. Its other sections (Transcriber, Footage Analyst, Researcher, Animator, Sound Designer, Finisher) describe responsibilities for selected work, not required separate model processes.
- The user selected a local visual editor workflow. Read `core/visual-editor.md` when preparing editable drafts, opening revisions in Studio or modifying an active visual project. Respect approved ranges in `jobs/JOB/editor/locks.json`; use `EditorStore.save` with the expected version for draft edits (or `EditorStore.propose` / `ai_editor.py propose` when the user should approve the change in Studio) and never strip locks or overwrite the visual project file to bypass them. User must explicitly unlock a conflicting range. Preview changes do not require an MP4 encode; final export still does.
- For every edit request, edit-treatment answer or revision feedback, follow `core/style-learning.md`: extract supported reusable style guidance, update the relevant skill and related documentation in the same task, and briefly report the scope. This maintenance is already authorized; do not ask for separate permission to edit those files. Keep one-video instructions local, merge duplicates, and preserve recorded job snapshots and creative choices.
- The user's primary platform is TikTok. Read `core/platforms/tiktok.md` when preparing TikTok suggestions and `preferences/default.json` for editorial preferences. This guides recommendations; unresolved framing, length, hooks, captions, visuals and audio still require the user's choices.
- Use `.venv/Scripts/python.exe ai_editor.py` on this Windows workspace. `doctor` reports local dependencies.
- Follow `core/interaction.md`: the prompt, existing job choices and explicitly authorized standing workflow take precedence over suggestions. Ask only for missing information that materially blocks the work. Analyze first and combine unresolved creative choices into one concrete proposal for approval; do not reopen fixed model/tool choices.
- The user selected the workflow of receiving one proposed treatment for approval before building. Preserve clear prompt choices and scoped delegation; do not require answering a full setup questionnaire again. New Footage Analyst/research/visual/audio choices can be included in that proposal before execution.
- Resolve the selected group profile from `profiles/`, reading its routing skill and relevant pinned packages. If none is selected, a candidate profile may scaffold a pending analysis job and be recommended in the proposal; it is not an approved style or a universal house default. Retired styles stay retired; existing jobs keep recorded snapshots.
- Create jobs with `new-job`. Copy source media, preserve the original. The initial plan keeps all footage and disables captions; it is a starting point, not a finished edit.
- After approval, build with the helpers instead of ad-hoc scripts: `cut` (approved source ranges to remove; edges land only in real pauses with a 0.15 s breath, ranges that would clip continuous speech are skipped and reported, layers/SFX/transitions are retimed; `--studio` sends the re-cut Studio draft as a proposal; follow `cut_policy` in `preferences/default.json` when choosing ranges), `captions` (balanced two-line items, Vietnamese compounds kept together) and `preview` (encodes the first seconds plus stills into `previews/`, outside the revision) before `render`.
- Standing local STT may run before complete creative setup so the proposal is based on the transcript. It records technical provenance in `transcript/processing.json`, without selecting setup/edit-plan decisions. After approval, record setup answers and the actual reply with `decide --stage setup`, apply the chosen treatment and record the exact edit plan. Preserve `transcript/raw.json`; log corrections in `cleaned.json`.
- The standing transcription choice is faster-whisper **large-v3 local**, currently `.tools/models/faster-whisper-large-v3`, CPU/int8 with word timestamps. Do not ask large-v3 versus small again. Use `transcribe JOB` to resolve the local choice; reuse matching existing/supplied transcripts and honor explicit no-STT decisions. Model/device changes require an actual override. Missing weights are an execution/setup issue: restore or obtain the same selected model, never silently switch or download as a scaffold test. On a new or missing installation, restore the same pinned model with `scripts/setup.ps1 -WithModel` (part of `-All`; resumable, checksum verified) or by copying the model folder; mention it once, not as repeated onboarding for each clip.
- Always offer the choice of using or skipping Footage Analyst. Recommend skipping it for a fixed-camera talking-head video, but do not silently decide. Ask about research and extra visuals too; describe unavailable tools/adapters before the user chooses them.
- Use FFmpeg for cutting, joining, picture transitions between clips, framing (pad/crop/blurred backdrop), constant per-clip speed, keyframed zoom/punch-in, captions, image/logo/B-roll layers, music and timed SFX. Speed, zoom, blur, transitions and SFX are creative choices to propose, not defaults of a group; anchor zoom keyframes and card reveals to transcript word times. Remotion source lives under `motion/` for MetricCard, BarChart, LowerThird, Keyword, KineticScene, Illustration (animated image card) and Points (phone-readable spoken points) assets; check `doctor` and install its dependencies through `scripts/setup.ps1 -WithMotion` before offering it as ready on a new machine. Use `render-motion` only when the user chooses a motion visual. Read `core/schemas/visuals-and-footage.md` before adding layers or motion specs.
- If footage analysis is selected, use `analyze-footage` to produce source-time frame samples, local scene/face/quality signals and crop proposals. Offer local-only analysis, AI inspection of the sampled images in the IDE, or Ollama semantics with an explicitly selected installed model. Local heuristics do not understand the narrative and proposals never edit the plan automatically.
- After implementing the user's selected proposal, record it with `decide --stage edit-plan --summary ... --user-message ...`. Render requires resolved choices matching the plan/config. `--dry-run` can prepare concrete commands before that choice. Do not record a reply the user never gave.
- No AI review role or automatic quality-repair loop. Export the selected edit and return its path/revision for the user to watch and prompt again. Report command failures as execution errors.
- Before changing an already exported video, run `revision --feedback ... --from-revision rNNN` for the version the user watched. That command clones a plan and logs feedback; you must apply the actual changes before rendering.
- Timestamp feedback refers to the watched revision's output timeline, not to raw source time. Recalculate clip mappings, caption timings and duration after edits.
- Revisions carry over explicit setup answers; ask about changes and any new decision. The feedback prompt itself can choose the requested revision. Do not reopen unchanged choices or introduce extra changes without asking. A plan/config changed after its recorded choice needs a new matching user selection before rendering.
- Do not overwrite a rendered revision or label a revision final unless the user chooses it. Pending revisions may be edited before their first export.
- Do not add unsupported plan fields and claim they were rendered. The current capabilities and limits are in `core/schemas/edit-plan.md`.

## Skill routing

- Read `core/skill-library.md` for installed sources, runtime limits and comparison workflow. `skills/library.json` pins 32 skills from the six Chrome source repos, plus the OpenChatCut connector. Upstream packages live in ignored `.tools/skill-library/`; restore them with `scripts/install_skill_library.py` and verify with `--check`. Installed skill files do not mean their native engines/services are configured.
- `.agents/skills/` (Codex) and `.claude/skills/` (Claude Code) each contain the same 40 repo-discoverable entrypoints: 33 packages, 6 groups and `video-edit`, the project workflow entry for any edit request. Use `$video-<source>-<skill>` in Codex or `/video-<source>-<skill>` in Claude Code for a specific package, and `$video-group-<group>` / `/video-group-<group>` for one group (some redundant prefixes are collapsed, e.g. `video-motion-prompt`). The name and exact source mapping come from `ai_editor.py skills` or the entrypoint. Follow an explicitly selected workflow; load its pinned SKILL.md and only needed helpers, preserving project locks/choices and runtime limits. Register missing entrypoints for both hosts with `scripts/register_skill_shortcuts.py`; do not edit upstream to rename it.
- `skills/styles/melvynx-raw/SKILL.md` / `melvynx-raw-vi`: raw/short-form, script, B-roll, style reference and repurpose. Research, account audit, translation and publishing helpers are scoped tasks, not automatic edit steps.
- `skills/styles/sunithvs-raw/SKILL.md` / `sunithvs-raw-vi`: talking-head/kinetic text and YouTube. Upstream macOS/Linux scripts require Windows porting before native execution.
- `skills/styles/wallstreet-finance/SKILL.md` / `wallstreet-finance-vi`: evidence/presenter/financial-technology explainer. Confirm language, framing and available engine; no automatic Chinese text, TTS or example media.
- `skills/styles/motion-catalog/SKILL.md` / `motion-catalog-vi`: named motion/transitions by catalog ID. Fetch the selected spec/kit, then port into the chosen composition.
- `skills/styles/review-variants/SKILL.md` / `review-variants-vi`: ad variants and timestamp feedback. Native Apple Silicon/macOS pipeline is not ready on Windows. Installed `video-qa` does not authorize an AI review role or automatic repair loop.
- `skills/styles/resolve-roughcut/SKILL.md` / `resolve-roughcut-vi`: editing inside DaVinci Resolve; requires app/scripting and respects upstream CC BY-NC 4.0 usage scope.
- `skills/domains/source-context/SKILL.md` keeps the existing profile domain slot while actual subject/language comes from the user's brief. Do not impose finance merely because the library contains a finance group.
- Select one main group per output and shared helpers only as needed. Do not load all installed skills or blend their defaults. For new raw footage, `compare-new` creates independent pending drafts from explicitly chosen profiles/format; actual edits still require choices or scoped delegation. Use `compare-view` after exporting to view outputs side by side. Never use a new comparison job to bypass approved ranges in an existing project.
- OpenChatCut connector: `.tools/skill-library/openchatcut/openchatcut/SKILL.md`. `core/openchatcut.md` records the UI assessment; app/MCP migration is not implemented. Do not treat its track locks as proven equivalents of this project's interval fingerprints.
- `core/platforms/tiktok.md`: shared TikTok guidance for opening, pacing, vertical layout and interface clearance; combine with the selected style/domain rather than replacing them.
- `core/style-learning.md`: required learning from edit/revision requests, with scope, evidence, skill/profile versioning and documentation updates.
- Maintain group-specific changes in routing packages under `skills/` with exact profile versions. Keep upstream packages immutable; update their source commit/checksum deliberately. These are project-local skills, not a change to unrelated global Codex skills.

## Changes to this code

- Keep local rendering usable without LLM API keys. The IDE agent supplies creative decisions and browser research; the CLI executes explicit plans.
- Test meaningful media behavior with `python -m unittest discover -s tests -v`. These are code tests, not an automated video-review stage.
- Runtime job data, video, downloaded tools and virtual environments are ignored by Git. Do not commit them or download model weights just for a scaffold test.
- Keep personal preference feedback in ignored `preferences/local-feedback.json`. `preferences/default.json` contains shareable defaults; do not commit chat history, private job data or local credentials.
